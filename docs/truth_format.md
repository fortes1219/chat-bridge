# truth 檔格式說明

> 給：寫導入指令、切塊、檢索程式的人，以及 `uv run chat-bridge truth` 叫來寫新檔的 agent（這份與詞表就是它的規則，採集目標、段落、key 也由程式從這份讀出來）。truth 檔是 `data/truth/` 底下的 Markdown，一個事件一檔。
> 相關檔：`docs/exposure_vocabulary.md`（分類詞表）、`tests/data/number_conversions.md`（數字轉換案例）。

## 一、檔名與 YAML

- 檔名：`YYYY-MM-DD-英文短名.md`，日期等於 `event_date`。
- YAML 的 key 固定、用英文，值照來源語言。不收表外的 key。

| key | 內容 | 誰決定 |
|---|---|---|
| `title` | 繁體中文標題；數字只能用阿拉伯數字或英文表示法（見第三節） | 依來源寫 |
| `event_date` | 事件發生日。來源沒給事件日時用發表日或該期起日，並在檔尾說明 | 來源 |
| `event_time` | 可省。事件發生或公開的時刻，ISO 8601 加時區（例：`2026-11-19T14:00:00-05:00`），在它自己的時區裡日期必須是 `event_date`。行情日的檔寫那個市場的收盤時刻。來源沒寫時刻就不寫這個 key | 來源 |
| `targets` | 屬於下列採集目標的哪幾個（1–5） | 判斷 |
| `markets` | `TW`、`US` | 判斷 |
| `tickers` | 來源點名的代號；台股代號加引號（`"2330"`），避免被讀成整數 | 來源 |
| `exposure` | 牽動的類別，只能用詞表裡的 20 個詞，表外一律拒絕 | 判斷 |
| `significance` | `key`、`supporting`、`background` 三選一 | 判斷 |
| `keyword_groups` | 每組是同一個概念的各種叫法（中英、代號、別名），不受數字規則限制 | 判斷 |
| `sources` | 每筆 `id`、`url`、`publisher`、`published`、`accessed`、`lang`、`format`。查不到發表日寫 `unknown`，不用讀取日頂替；頁面只顯示年月就寫年月 | 來源 |

採集目標（`targets`）：

1. 2026 年 6 月起的台股與美股相關消息。
2. 聯準會近半年的動向，哪些行為導致股市動盪。
3. 川普、輝達、中國、台積電與供應鏈、微軟財報。
4. 微軟與其他大型科技公司的 AI 投入尚未回收、又開啟下一輪舉債，引發疑慮而使股市動盪的消息。
5. 這波下跌是否有權威說法指出股市回到正常趨勢。

## 二、內文三段（固定標題）

1. `## 事件發生`：發生了什麼。財報檔至少留一條用來源原話寫的「誰在哪天公布了什麼」。**行情日慣例**：當天主要指數的收盤本身就是事件，放這一段。
2. `## 影響股市證據`：來源明寫的行情變動與歸因——其餘指數、成交值、法人買賣超、記者或分析師寫的漲跌原因。政策文件裡的描述、公司的支出與舉債數字不算行情，不放這裡。
3. `## 相關標的`：來源寫到的個別標的的事實——個股、ETF、債券與公債殖利率、匯率、商品（油價）的漲跌與價格，以及公司自己公布的數字。
4. `## 後續與不同說法`（可省）：之後的發展、不同立場的看法、預測。

- 某一段沒有內容時，寫一行引言區塊（`> 本檔讀過的來源沒有…`），不標來源。
- 檔尾一行 `> significance 依據（key|supporting|background）：…`，寫明是哪一條判準，不標來源、不進三段。

## 三、數字規則

- 中文來源條目與所有標題裡，用中文數字或中文量級（萬、億、兆）寫的數量，以及成數、碼、民國年，一律轉換：
  - 金額：幣別＋英文表示法，保留全部有效位數。例：1774.18億元 → NT$177.418 billion；1兆2461.04億元 → NT$1.246104 trillion；194.02億美元 → US$19.402 billion。
  - 非金額的數量：阿拉伯數字、不加千分位。例：4萬點 → 40000點；9萬9930口 → 99930口。
  - 成數 → %（6成 → 60%）；碼 → 個百分點（1碼 → 0.25個百分點、半碼 → 0.125個百分點）；民國年 → 西元年。
  - 「多／逾／近／約／超過」保留，放在轉換後的數字前（8100多億美元 → 逾 US$810 billion）。
  - 沒寫幣別的不補幣別（千億規模預算 → 100 billion 規模預算）。
  - 不轉：名稱與固定用語裡的數字（五大策略、5大措施、三大法人、一度、萬一），以及本來就是阿拉伯數字的排名（第4大）。
- 轉過數字的句子不是逐字了：拿掉引號，改成轉述。
- 英文來源不動（$96.2 billion、1/4 percentage point、3-3/4 to 4 percent 照留）。
- 每一筆轉換記進 `tests/data/number_conversions.md`：檔名｜原寫法｜轉成什麼｜註。

## 四、寫法通則

- 一條只寫一件事、只標一個來源，結尾標 `[sN]`，對應 `sources` 的 `id`。
- 每一條用它來源的語言寫：英文來源寫英文，中文來源寫中文。
- 不判斷報導真假，也不加推論、比較或定性。不同來源說法不同時分條並列，不加比較句。
- a. 標題的數字只能是阿拉伯數字或英文表示法；標題不能寫來源沒有的動作或定性（例如「上調」「多數」「小跌」「隔天」）。
- b. 引號只包住實際照錄的那一段；句點放在引號外；截斷的句子用刪節號「…」表示後面還有。
- c. 不寫「來源沒有提到 X」當條目。需要說明時放引言區塊、不標來源。
- d. 不加時態與語氣：來源寫 continue 就不寫 will continue。
- e. 不替來源換名詞：benchmark U.S. crude 不寫成 WTI，Big Tech companies 不寫成 hyperscalers，「下探」不寫成「最低」，「集中市場指數」不寫成「加權指數」。
- f. 條件句、時間基準、說話場合不能省：if、even if、from … late Thursday、told … in an interview、盤中 vs 收盤、「截至昨天」，都照寫。
- g. 來源沒有引號的話不加引號：中文的「某某表示，…」「某某指出，…」是間接敘述，寫成轉述。
- 盤中數字要標明是盤中。
- 引用滾動頁（例如 BLS 的最新一期頁）時改用有日期的存檔頁網址。

## 五、來源

- 優先：官方與公司自己的公告、申報文件（SEC、聯準會、央行、金管會），其次才是媒體。
- robots 或條款擋自動讀取的網站不直接讀（例如證交所網站、路透本站）；合法轉載它稿子的網站可以讀，`publisher` 寫「轉載站（原通訊社）」，`url` 寫實際打開的頁。
- 每一句事實都要出自實際打開過的頁面；這段期間在模型訓練截止之後，不能用記憶補。

## 六、給寫程式的人的提醒

- 條目裡的「今天」「昨天」「今年」「明年」「本年」「Thursday」是相對於該來源發表日的說法，照來源寫、沒有換成日期。切塊時每個片段要帶上這個檔的 `event_date` 與該條來源的 `published`，否則檢索出來的片段會讓模型不知道「今天」是哪一天、「明年5.82%」是哪一年。

## 七、`## 當日與之後的行情`（程式算的段落）

> 對齊規則是設計上的選擇，可以更正。

- 由指令產生：`uv run chat-bridge truth` 寫新檔時一併算好；已經有的檔用 `uv run chat-bridge collect <新聞檔或資料夾>` 重算。只有這一段的格子或註變了才改寫檔案，檔裡其他內容逐位元組不動。
- 位置：「相關標的」之後、「後續與不同說法」之前。段落第一行寫明「由程式依日線收盤價計算」，數字不是新聞來源的話，不用 `[sN]` 標記；資料來源記在 sources 的 `d1`（Yahoo），用到 FinMind 補的日子時另有 `d2`。表格底下手寫的註留在原處。
- 資料：Yahoo Finance 日線；序列與市場列在 `data/market_series.json`，範例是九個：^TWII、2330.TW、2308.TW、0050.TW、006208.TW、^GSPC、^IXIC、^DJI、^SOX。Yahoo 缺的台股日子由 FinMind 的日收盤補，註欄寫「YYYY-MM-DD 的收盤取自 FinMind」。
- 兩種對齊，看檔裡有沒有 `event_time`：
  - 有 `event_time`：各市場的 D0 是收盤時刻在 `event_time` 當下或之後的第一個交易時段，對準日欄是那個時刻在該市場的日期；事件發生在 D0 這一盤的交易時間內的，註欄寫明。第一行寫出事件時刻。
  - 沒有 `event_time`：照下面的日期對齊。2026-11-17 以前的檔都是這一種。
- 收盤用原始 close，**未調整除息**；四捨五入到兩位，百分比兩位。視窗內（D-2 之後到 D+5）有除息日的列，在「註」欄寫明。
- 交易日：各序列用自己市場的交易日；同一市場的交易日曆取該市場所有序列日期的聯集。某序列缺某一天、FinMind 也沒有時，用到那一天的格子寫「沒有資料」並在註欄寫「Yahoo 回應缺 YYYY-MM-DD 這一根」。成交量 0 且開高低收相同的那一根是 Yahoo 在非交易日補的佔位，不算交易日。下載當天還沒收盤的那一根不採用。
- 對齊：事件市場＝`markets` 的第一個。US 事件：美股序列對準 event_date，台股序列對準 event_date 隔天（台股收盤在美股開盤之前）。TW 事件：兩邊都對準 event_date（美股在台股收盤後才開）。D0＝對準日當天或之後的第一個交易日；event_date 不是交易日時加一行說明。
- 欄位：前一交易日漲跌%＝D-1 相對 D-2（用來看台股當天反應的是美股哪一盤）；當日%＝D0 相對 D-1；次一交易日%＝D+1 相對 D0（盤後才公布的事件看這一欄）；D+5 累計%＝D+5 相對 D-1。
- 資料還沒有的格子寫「沒有資料」，不留白、不補估計值。
- 這一段只是行情數字，不判斷因果；新聞寫的歸因留在「影響股市證據」，兩者可以對照。
