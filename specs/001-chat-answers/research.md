# Research: Chat answers from retrieved passages

Each decision names what was chosen, why, and what else was looked at. Line numbers refer to
the commit given, or to the branch and date when no commit was pinned.

## 1. Answer flow

- **Decision**: Search with the question as asked, take the best sections, and let the model
  answer from them. The search runs before the answer starts streaming.
- **Rationale**: This is the simple flow of the Azure rag-postgres template, the template the
  knowledge base already follows. In `rag_simple.py:59-85` (Azure-Samples/rag-postgres-openai-python
  `ecaafc4`), the search uses the original question; `routes/api_routes.py:169-194` uses the simple
  flow unless the advanced one is asked for, and searches before streaming.
- **Alternatives**: The template's advanced flow rewrites the question with a model call first;
  Vibe-Trading lets the model decide which tools to call (`--json-schema`). Neither is needed
  when there is one search and nothing for the model to decide.

## 2. Transport

- **Decision**: `POST /chat/stream` with a JSON body. The reply is NDJSON. The first line is the
  context; each later line is a piece of the answer. An error after the stream starts becomes a last
  line `{"error": ...}`.
- **Rationale**: Azure `routes/api_routes.py:152` (the endpoint), `:32-44` (`format_as_ndjson`),
  and `api_models.py:71-74` (`RetrievalResponseDelta`: `type`, `delta`, `context`).
- **Alternatives**: WebSocket or Socket.IO. Of the chat projects sampled for this repository, most
  stream over plain HTTP.

## 3. The answering model

- **Decision**: The user's own Claude Code, started as `claude -p` for each answer, with every
  built-in tool and MCP server off. The system prompt comes from a file. The sources and the
  question come in on standard input. `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN` and
  `ANTHROPIC_BASE_URL` are removed from the child's environment. The login is checked with
  `claude auth status` before each answer, in the same environment.
- **Rationale**: HKUDS/Vibe-Trading `b412055`, `agent/src/providers/claude_cli.py`:
  - `:55-61`: the isolation flags `--restricted`, `--strict-mcp-config`, `--tools ""`,
    `--no-session-persistence`;
  - `:63-69`: the key variables removed;
  - `:115-140`: the login check;
  - `:287-288`: the system prompt file;
  - `:295`, `:305`: the input on standard input.

  No text from the user or the documents is on the command line, and with no tools the model can
  only write text.
- **Alternatives**: An API key for the Anthropic API. Rejected: the demo must run on the visitor's
  own login and plan, never on the author's key.

## 4. Streaming the answer

- **Decision**: Read Claude Code's `stream-json` output with partial messages, and pass on each
  `text_delta` as it arrives. If no partial message comes through, send the final `result` text
  once.
- **Rationale**: anthropics/claude-agent-sdk-python `69846cdf82ae`:
  - `_internal/transport/subprocess_cli.py:523`: starts the CLI with
    `--output-format stream-json --verbose`;
  - `:644`: adds `--include-partial-messages`;
  - `_internal/message_parser.py:347-352`: reads `stream_event` (a raw API stream event);
  - `:310-323`: reads `result`.

  Azure `rag_simple.py:141-143` sends each text delta as it comes.
- **Alternatives**: `--output-format json`, which returns the whole answer at the end
  (Vibe-Trading). Kept only as the fallback.

## 5. Failure, time limits and line length

- **Decision**: A run fails when there is no `result`, when `result.is_error` is true, when the exit
  code is not 0, or after 600 seconds. The login check gets 15 seconds. One output line may be up to
  1 MB.
- **Rationale**:
  - Vibe-Trading `b412055` fails a run that wrote no result or whose result is an error
    (`claude_cli.py:324-333`). It also uses a 600 s floor per turn and a 15 s login check
    (`claude_cli.py:40-41`).
  - The Agent SDK fails a process that exited with a code other than 0
    (`subprocess_cli.py:1107-1113`). Its default buffer limit is 1 MB (`subprocess_cli.py:42`).
  - asyncio's default line limit, 64 KB, is too small for a final result that holds the whole
    answer.

## 6. Sources and disclaimer come from the app

- **Decision**: The sources and the disclaimer go out in the first line, built by the app from the
  search result. The model is told not to write them.
- **Rationale**: In Azure `rag_simple.py:125-128`, the app puts the found items into the response
  context. A text the app sends cannot be dropped by a model that has been led astray.
- **Disclaimer wording**: The disclaimer is one fixed text in Traditional Chinese and English. It
  says the answer is generated by AI from public data and is not investment advice. A public
  finance agent project puts the same kind of notice at the top of its README: virattt/ai-hedge-fund
  `README.md:3`, `:12-14` ("educational and research purposes only").

## 7. How many sections

- **Decision**: the eight best sections.
- **Mechanism**: take the top N of the search and make N a setting. This is what Azure
  `api_models.py:15` (`top: int = 3`) and MaxKB `v2` `apps/application/models/application.py:43`
  (`top_n: 3`) do. Both default N to 3, and this feature started with 3.
- **Why 8, measured on this data** (search in the test container, 2026-11-20, with the two
  acceptance questions of US1):
  - The Chinese question's top 8 all score 0.0292 to 0.0309, and both search methods found each
    of them. From the 9th the score drops to 0.0164, and only one method found it.
  - The top 3 were 2026-11-10 (two sections) and 2026-11-05. The Fed events that answer the
    question rank 4th to 8th: the September rate rise, the June meeting (two sections), the
    Jackson Hole speech, and the 10-year yield above 5%.
  - With three, the first real run's answer said the data held only the 2026-11-10 event for the
    Fed, which is wrong about the data.
  - The English question's top 3 were the three Fed meetings and speeches. The two questions share
    no file in their top 3, but share four in their top 8: 2026-09-16, 2026-08-28, 2026-06-17 and
    2026-11-10.
- **Cost**: the model's input grows from three to eight sections. One question is still one search
  and at most one model run.

## 8. A question the search finds nothing for

- **Decision**: Do not call the model. Reply with a fixed text in both languages that says the data
  has nothing on it.
- **Rationale**: MaxKB `v2` `application.py:44-46` (`no_references_setting`) decides what to reply
  when no paragraph is found, and one of its settings is a set answer. Not calling the model also
  saves the user's plan usage and leaves no room to answer from outside knowledge.

## 9. Recording questions

- **Decision**: One row per question in a new `chat_records` table: question, answer, time, and
  `details`. `details` holds the sections found, the text sent to Claude Code, and the error, if any.
  The questions the data cannot answer are the rows whose section list is empty.
- **Rationale**: MaxKB `v2`:
  - `apps/application/models/application_chat.py:88-111`: `ChatRecord` keeps the question, the
    answer and `details`;
  - `apps/application/chat_pipeline/step/search_dataset_step/impl/base_search_dataset_step.py:135-150`:
    the search step keeps its paragraph list in the details.

  Dify `api/models/dataset.py:670` (main, 2026-11-20) also records every query.
- **Alternatives**: A separate "unanswered" flag. Not found in the projects sampled; the empty
  section list already says it.
- **Limits**: A question may be up to 10,240 characters, as MaxKB's `problem_text`
  (`application_chat.py:99`). A list request returns 1 to 10,000 rows, the range the search
  command already allows after MaxKB.

## 10. Starting the service

- **Decision**: `uv run chat-bridge` with no subcommand starts the service on 127.0.0.1:8000;
  `ingest` and `search` stay subcommands.
- **Rationale**: khoj-ai/khoj (master, 2026-11-20) `pyproject.toml:106-107`
  (`khoj = "khoj.main:run"`) and `src/khoj/main.py:119-234`: the bare command starts the server.
  FastAPI's `docs/en/docs/fastapi-cli.md:29`: `fastapi dev` listens on 127.0.0.1; `:130`:
  `fastapi run` listens on 0.0.0.0, which makes the service public.

## 11. Keeping other web pages out

- **Decision**:
  - keep FastAPI's strict `Content-Type` check for JSON bodies;
  - add no CORS rule;
  - accept only requests whose `Host` is `127.0.0.1` or `localhost`, with Starlette's
    `TrustedHostMiddleware`.
- **Rationale**: fastapi/fastapi `05e6df7e906c3decba377c37548019973f40bf15`:
  - `docs/en/docs/advanced/strict-content-type.md:3`, `:7-17`, `:21-64`: the strict check is the
    default, and it stops a page from posting to a local AI agent without a CORS preflight;
  - `docs/en/docs/advanced/middleware.md:62-70`: `TrustedHostMiddleware`.

  ollama/ollama `73ee71d`, `server/routes.go:2288-2345` and `:2384-2390`: a local model server
  that checks the `Host` header the same way.

## 12. Prompt injection

- **Decision**: No tools. The sources and the question reach the model separately, between their
  own tags, and the system prompt says neither can change its rules. The sources and disclaimer are
  sent by the app. Attack tests use a direct and an indirect injection.
- **Rationale**: OWASP Top 10 for LLM Applications `99f4395`, `2_0_vulns/LLM01_PromptInjection.md`:
  - `:13-19`: direct and indirect injection;
  - `:34`: no fool-proof prevention;
  - `:36-60`: mitigations, among them least privilege, separating and marking external content,
    and adversarial testing.

  promptfoo `eb0f11f`, `site/docs/red-team/plugins/indirect-prompt-injection.md:8`, `:36-40`: put
  the attack in the untrusted data; the test fails if the model follows it. Azure
  `evals/safety_evaluation.py:29-47`, `:69-84` attacks its own local chat endpoint.

## 13. The system prompt

- **Decision**: The system prompt says:
  - answer only from the sources, and say so when they do not hold the answer;
  - cite each source by its number;
  - give event dates;
  - answer in the question's language.

  Today's date goes in as `{{CURRENT_DATE}}`.
- **Rationale**: Azure `src/backend/fastapi_app/prompts/answer.txt:4-9` and open-webui/open-webui
  (main, 2026-11-20) `backend/open_webui/utils/task.py:102`.

## 14. The model reads each section's own text

- **Decision**: The search result carries each section's id and full text. The chat sends the full
  text to the model.
- **Rationale**: In Azure, the search returns whole rows, and `rag_base.py:49-51` builds the model's
  "Sources" from each item's full text. A snippet of about 120 characters is too little to answer from.
- **Alternatives**: Look the section up again by file and heading. Rejected: a heading path is not
  unique within a file.

## 15. The embedded database has no password

- **Decision**: State in the README that the service is for one person on that machine.
- **Rationale**: pixeltable-pgserver 0.7.2 `postgres_server.py:201-214` runs `initdb` with
  `--auth=trust` and offers no option to change it. On Windows it listens on a port on 127.0.0.1
  (`:257-262`); elsewhere it uses only a socket (`:244-254`).

## 16. Listing the unanswered questions without scanning every record

- **Decision**: A partial index on `chat_records (id)` that holds only the rows whose section list is
  empty. The unanswered list reads the newest rows from that index; the full list reads the newest
  rows by primary key. Both take a limit.
- **Rationale**: The PostgreSQL 16 manual, "Partial Indexes"
  (https://www.postgresql.org/docs/16/indexes-partial.html), Example 11.2: an index on `orders
  (order_nr)` with `WHERE billed is not true` serves the query for the few rows a workload asks for.
  The project's rules say every query has an index and nothing scans all stored data.
- **Alternatives**: A separate count column. Rejected: it would repeat what the section list already
  says.
